## 13. Débito técnico criado

| Item | Detail |
|---|---|
| Session (M03) not wired into the Service Locator | `SessionFactory`/`WebSessionManager` are not part of the `RuntimeInstance` bootstrap flow today (pre-existing condition, unchanged by C.5) — no fake service was registered to avoid inventing wiring beyond this slice's scope. Revisit when Session is integrated into the instance lifecycle. |
| Route → permission code convention | `canActivate()` derives a permission code from `route.permission` / `route.requiredPermission`, falling back to `${moduleId}.access`. This convention is not yet formalized in `docs/runtime-implementation/03-INTERFACES.md` or the CRB schema — it is a minimal, additive convention that does not require a CRB schema change. A future slice (or SSOT amendment) may want to make this explicit. |
| `filterVisible` "no metadata = public" rule | Items without `permission`/`requiredPermission`/`resource`+`action` metadata are treated as visible by default (no fail-closed on absence of metadata), since no current CRB object type is universally tagged with permission metadata. Documented here for visibility, not hidden in code. |

No other new debt. No architectural violations. No parallel engines created.
